Just These Buttons

A one-page web app: a family member photographs a machine, names one task, checks the buttons the AI kept, and prints a card and number stickers for the real machine.

The three pieces

The page

Everything the caregiver sees and does, held in one reducer in memory. Nothing is saved.

One server route

/api/find-buttons keeps the API key, limits requests, checks the reply.

Gemini 3.8 Flash

Returns each needed control as a box on a 0–1000 grid over the photo.

One action, followed through the code

What happens when the caregiver presses Find the buttons:

  1. The page sends the photo and task pagecomponents/JustTheseButtons.tsx · async function find()
  2. The route limits, validates, and asks the model serverapp/api/find-buttons/route.ts · POST → lib/gemini.ts · findButtons
  3. The model reads the photo against the prompt Geminilib/prompt.ts · buildPrompt
  4. The reply is cleaned into at most five steps serverlib/schema.ts · normalise
  5. The photo dims except the kept buttons; numbers are placed beside them pagecomponents/ButtonOverlay.tsx · mask + placeBadges (lib/badges.ts)

A three-stop route (reference route: not yet walked through together)

1 · Where the request leaves the page — components/JustTheseButtons.tsx

Search for async function find(). It posts the photo and the trimmed task, then turns each answer into one state: 429 into “wait a little”, 413 into “photo can't be used”, a network error into “try again”. Every path keeps the photo and task.

if (res.status === 429) return dispatch({ type: "failed", kind: "rate_limited" });
if (res.status === 413) return dispatch({ type: "failed", kind: "unusable_photo" });
if (!res.ok) throw new Error(`find-buttons ${res.status}`);
dispatch({ type: "found", result: (await res.json()) as FindButtonsResult });
2 · What the model is told — lib/prompt.ts

Search for buildPrompt. The line that mattered most came from the vision probe: without it, the model assumed the machine was already on and left out the power button.

Assume the machine starts switched off, with nothing set: the person is walking
up to it cold. So if it has a power or on/off button, switching it on is the first step.

The call itself is findButtons in lib/gemini.ts: image sent at high resolution, JSON schema, LOW thinking, 25-second timeout.

3 · How the screen shows “just these buttons” — components/ButtonOverlay.tsx

Search for -keep. The photo is drawn twice in one SVG: a dimmed copy, then the original shown only through a white rectangle per step in a mask. Because the SVG's viewBox is 0 0 1000 1000, the model's box numbers are used exactly as returned.

<mask id={`${id}-keep`}>
  <rect width="1000" height="1000" fill="black" />
  {steps.map((s) => <rect … fill="white" />)}
</mask>

Numbers are placed by placeBadges in lib/badges.ts so they never cover a kept button or each other.

A practice to reuse

Probe the riskiest assumption before building the interface, using the same function the app will call.

The whole product rested on the model putting boxes on the right controls. scripts/probe.ts ran the app's own findButtons over eleven photos and drew every box. It showed the boxes were fine and the choice of controls was not. Changing one sentence at a time, and running each version more than once, found the fix; raising the thinking level didn't help. The rounds and numbers are in docs/vision-probe.md.

On another project: when an AI output is the foundation, write a small script that runs the real call over a handful of realistic inputs and renders the result for eyes, then change one thing at a time and repeat each run.
